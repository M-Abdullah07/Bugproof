# Domain documentation

Single-context project: read root `GLOSSARY.md` when using or changing domain
terms. Read `docs/specs/bugproof.md` for implementation planning or acceptance.

Read root `Decisions.md` before changing a tradeoff; it is the decision ledger.
Read `Architecture.md` for ownership and planned paths. Add a linked ADR only
when an entry needs a longer rationale; no ADR directory exists yet. Keep one
authoritative decision entry rather than maintaining competing ledgers.
Earlier candidate and research documents are historical context, not contracts.
